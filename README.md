# FORMA

Демонстрационное Android-приложение на Flutter. Экраны основаны на экспорте FORMA; часть новых экранов ещё требует визуальной сверки с макетами на устройстве. Дневник хранит данные в памяти; сканер блюда использует API при его настройке, иначе — демонстрационные данные.

Короткая карта экранов и кода — в [PROJECT_GUIDE.md](PROJECT_GUIDE.md).

## Запуск проекта

Проект создан на Flutter 3.47.0 (Dart 3.13.0). Откройте папку `fitness_trainer` в IDE, настройте Android SDK и выполните:

```sh
flutter pub get
flutter run
```

Типизированные маршруты и ссылки на ассеты уже включены в исходники. После добавления маршрута или ассета обновите их командой `dart run build_runner build`.

## Сценарии

- Регистрация подтверждается локальным кодом `12345678`; вход проверяет введённые поля. Авторизация через Google и Apple пока не подключена.
- Анкета собирает параметры, цель и сведения о здоровье; план и нормы в демо основаны на локальных примерных значениях.
- Главная и питание используют общий дневник в памяти. Добавление продукта и сохранение результата сканера обновляют калории и КБЖУ.
- База упражнений содержит локальные данные. Поиск, фильтры, замена упражнения и чекбоксы подходов в тренировке работают без сервера.
- Сканер блюда делает фото камерой устройства или выбирает его из галереи и показывает распознанное блюдо, КБЖУ и редактируемый вес порции. Если URL API задан, фото отправляется на сервер; иначе используется демо-ответ. Для серверного распознавания задайте URL при запуске:

  ```sh
  flutter run --dart-define=FOOD_ANALYSIS_URL=https://your-server.example/analyze
  ```

  Если URL не задан, приложение использует явно помеченные демонстрационные данные, чтобы проверить подтверждение и сохранение без сервера. Эти примерные данные не распознают и не отражают содержимое фотографии.

  API принимает `POST multipart/form-data` с файлом в поле `image` и возвращает JSON с полями `name`, `weight_grams`, `calories`, `protein`, `fat`, `carbs`; `confidence` (0–1) и `ingredients` (`[{ "name": "...", "grams": 120 }]`) необязательны. Значения КБЖУ и граммы ингредиентов должны соответствовать порции `weight_grams`. Штрихкод пока не сканируется.
- Профиль и его разделы реализованы как демонстрационный сценарий. До входа показывается пример имени; затем имя и почта берутся из формы входа. Изменения хранятся в памяти. В настройках можно переключить тёмную и светлую темы. Галерея компонентов доступна по маршруту `/ui-kit`.

Данные в памяти сбрасываются при перезапуске приложения.

## Структура

- `lib/features/` — экраны и состояние по сценариям: старт, вход, анкета, основной раздел.
- `lib/features/dashboard/food_catalog.dart` и `exercise_catalog.dart` — локальные каталоги для демонстрации.
- `lib/ui_kit/` — тема и переиспользуемые компоненты.
- `lib/router/` — конфигурация и сгенерированные маршруты `auto_route`.
- `lib/gen/` — сгенерированные FlutterGen ссылки на шрифты и SVG-иконки; файлы не редактируются вручную.
- `assets/` — шрифты и иконки. Их лицензии находятся в `licenses/`.

Проект содержит только Android-платформу. Локальные настройки SDK, кэш и результаты сборки в архив не включены.
